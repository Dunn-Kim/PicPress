<h1 align="center">Magic Pics</h1>

<p align="center">해상도와 화질은 그대로, 용량만 줄이는 macOS 사진 압축 앱</p>

---

폴더를 지정하면 하위 폴더까지 모든 사진을 원본 해상도 그대로 다시 압축합니다.
결과가 **원본과 눈으로 구분되지 않을 때만**, 그리고 **용량이 10% 이상 줄어들 때만** 원본을 교체하며,
원본은 지우지 않고 휴지통으로 보냅니다. 외부 라이브러리 없이 macOS 내장 ImageIO만 사용하고,
모든 처리는 내 Mac 안에서 끝납니다.

## 주요 기능

- **폴더 일괄 처리** — 경로 입력, 폴더 선택, 드래그 앤 드롭. 하위 폴더 포함, 숨김 파일과 패키지(사진 보관함 등)는 건드리지 않습니다.
- **해상도·픽셀 유지** — 크기를 줄이거나 늘리지 않고, 같은 해상도로 다시 인코딩만 합니다.
- **장마다 화질 검증** — 원본과 결과를 픽셀 단위로 비교해 기준을 통과해야만 교체합니다.
- **HEIC 우선, JPEG 대체** — HEIC가 기준에 못 미치는 사진은 JPEG(품질 90%)로 다시 시도합니다. 호환성이 중요하면 "JPEG만" 모드를 쓰세요.
- **메타데이터 보존** — EXIF(촬영일·카메라 정보), GPS, 방향, 색 프로필을 유지하고, HDR 게인맵 보존 옵션을 켜고 인코딩합니다. 파일 생성일·수정일·권한도 그대로 옮깁니다.
- **안전한 교체** — 새 파일은 원자적으로 배치되고, 실패하면 원래 상태로 되돌립니다. 원본은 휴지통에서 언제든 복구할 수 있습니다.
- **재실행 안전** — 처리한 파일에는 확장 속성(`app.picpress.optimized`, 이전 이름 PicPress 시절부터 쓰던 이름 그대로)이 붙어 다음 실행 때 건너뜁니다.

## 화질 기준

HEIC는 품질 80%, JPEG는 품질 90%로 인코딩한 뒤, 결과를 원본의 색공간(RGB가 아니면 Display P3)에서
8비트로 그려 원본과 비교합니다.

| 항목 | 기준 |
|---|---|
| 전체 PSNR | 40 dB 이상 |
| 32×32 픽셀 영역별 PSNR | 모든 영역 35 dB 이상 (전체 평균에 가려지는 국소 손상을 잡기 위해) |
| 투명도(알파) | 변하지 않아야 함 |
| 용량 | 원본보다 10% 이상 작아야 함 (손실 압축을 반복할 이유가 없도록) |

PSNR 40 dB 이상이면 일반적으로 눈으로 구분하기 어렵다고 봅니다. 색 배경 위의 색 글씨처럼
색 정보가 섬세한 이미지는 HEIC·JPEG 모두 기준을 넘지 못하므로 원본이 그대로 유지됩니다.

## 건너뛰는 파일

원본을 교체하면 정보가 사라질 수 있는 파일은 손대지 않습니다.

| 표시되는 사유 | 대상 |
|---|---|
| 지원하지 않는 형식 | JPEG·PNG·HEIC/HEIF·TIFF·BMP·WebP 이외 (RAW, PSD, GIF 등) |
| 여러 장이 든 파일 | 애니메이션, 여러 페이지 TIFF 등 |
| 이미지 외 데이터 포함 | 삼성·구글 모션 포토의 동영상, 삼성 갤러리 편집 이력, 덧붙은 미리보기·게인맵 이미지 |
| 16비트 이미지 | 편집용 고정밀 원본 (10비트 원본은 10비트를 유지하는 결과만 허용) |
| HDR 이미지 | PQ·HLG 색공간 |
| 화질을 유지하며 충분히 줄일 수 없음 | 화질 기준 또는 10% 절감 기준 미달 |
| … 파일이 이미 있음 | 확장자가 바뀔 때(예: `a.png` → `a.heic`) 같은 이름의 파일이 이미 있는 경우 |
| 이미 처리됨 / 심볼릭 링크 | 재실행, 링크 파일 |

잘리거나 손상된 파일은 "이미지를 읽을 수 없습니다"로 표시되고 그대로 둡니다.

## 요구 사항

- macOS 15 이상
- 빌드: Xcode 26 이상 (Swift 6.2 이상). `build.sh`는 빌드하는 Mac의 아키텍처(Apple Silicon 또는 Intel)용 앱을 만듭니다.

## 빌드와 설치

```sh
git clone https://github.com/Dunn-Kim/MagicPics.git
cd MagicPics
./build.sh                                  # "build/Magic Pics.app" 생성 (ad-hoc 서명)
ditto "build/Magic Pics.app" "/Applications/Magic Pics.app"
```

테스트:

```sh
swift test
```

아이콘을 고쳤다면 `swift Icon/make-icon.swift`로 `Icon/AppIcon.icns`와 `Icon/AppIcon.png`를 다시 만듭니다.

> 직접 빌드한 앱은 ad-hoc 서명입니다. 내려받거나 다른 Mac에서 복사해 온 빌드를 Gatekeeper가 막으면,
> 한 번 실행을 시도한 뒤 시스템 설정 → 개인정보 보호 및 보안에서 "그래도 열기"를 누르세요.

## 사용법

1. 폴더 경로를 입력하거나(`~` 사용 가능, 터미널에서 복사한 경로도 됨) **선택…** 을 누르거나, 폴더·사진을 창에 끌어다 놓습니다.
2. 형식을 고릅니다: **HEIC 우선**(더 작음) 또는 **JPEG만**(호환성).
3. 확인 창에서 **압축 후 원본 교체**를 누릅니다.
4. 결과 목록에 파일별 용량 변화와 건너뛴 사유가 표시됩니다. 돋보기 버튼으로 Finder에서 결과 파일을 볼 수 있습니다.

교체된 원본은 휴지통에 있습니다. 결과를 확인한 뒤 휴지통을 비워야 디스크 공간이 실제로 확보됩니다.

## 프로젝트 구조

```
Sources/MagicPics/
├── App/          진입점, 창
├── Engine/       압축 판단 — 출력 형식, 인코딩·검증, 화질 비교, 파일 구조 검사
├── FileSystem/   폴더 탐색, 원자적 교체·휴지통·처리 표시
├── Batch/        작업 상태, 동시 처리(최대 4개), 확인 흐름
└── UI/           화면
Tests/MagicPicsTests/  같은 구조의 테스트
Icon/                  아이콘 생성기와 결과물
build.sh, Info.plist   앱 번들 빌드
```

## 알려진 한계

- Finder 태그 등 일부 확장 속성은 새 파일로 복사되지 않습니다.
- 같은 이름으로 교체하는 순간 앱이 강제 종료되면, 원본은 휴지통에 남고 결과 파일은 사라질 수 있습니다.
- Ultra HDR JPEG처럼 이미지 뒤에 데이터가 붙은 파일은 안전을 위해 모두 건너뜁니다.
- 매우 큰 이미지를 여러 장 동시에 처리하면 메모리를 많이 씁니다 (작업자당 디코딩된 이미지 + 비교용 사본 2개).
